# 星枢 OpenClaw 桌面改进审计报告

审计基线：Tulu `4.4.8` (`1c16d69a`) 与 ClawPanel `0.19.1` (`cc3bf3b`)。

## 结论

Tulu 的优势是工具生态和内容工作台：Browser Use 隔离安装、CLI-Anything、Agency Agents、OpenMontage、影视/音乐及可视化办公入口。ClawPanel 更偏运行治理：统一模型渠道、安装升级安全、Linux/Web/Docker 升级策略、便携模式和 Hermes 运营导航。

本轮采用“按契约吸收”原则，不覆盖双方已有模块，也不把仅有品牌展示或外部服务依赖的页面当作能力迁移。

## P0 改进状态

- 更新链：已强制使用构建期注入的受信 HTTPS 清单；下载项必须有 SHA-256；安装包 URL 和哈希由后端重新读取清单核对；重定向后必须保持 HTTPS、同主机和同端口。未配置清单时自动更新安全停用。尚未接入签名清单的前端 ZIP 热更新已整体停用，因此不再接受任意 URL、空哈希或 ZIP 条目。
- IPC 与工作区：`assistant_exec` 仅允许可信 `main` 窗口调用；Memory 和 Agent 工作区读写使用 canonical 路径边界，阻断工作区内部符号链接逃逸。
- 渲染安全：渠道验证、Hermes Provider、服务错误和播放器远端标题改为文本节点或显式转义，播放器不再加载 `file://` 页面或 localhost 开发桥。
- 厂长播放链：每集播放页通过受限后端命令解析，仅接受 `https://4kcz.com`/`www.4kcz.com` 的 `/v_play/` 页面；解析不到真实媒体 URL 时明确失败，不把 HTML 页面误交给播放器。
- 发布门禁：tag `v*` 可触发 CI；三平台使用 `tauri build` 生成安装包；构建和发布依赖 lint、Rust、前端、E2E 和安全任务；Node 依赖统一使用 `npm ci`。
- 统一模型渠道中心：后续新增独立数据模型、凭据遮罩、原子写入和 OpenClaw/Hermes/助手三套适配器。
- 便携模式：仅在完成路径清洗、运行时定位、数据迁移、资源体积和许可证清单后评估接入。
- 浏览器自动化：保留 Tulu 现有隔离运行时、域名白名单、权限和卸载清理；不能用普通浏览器窗口替代。

## P1

- 首次引擎选择器值得吸收；不直接移植仅有品牌落地页的“心甜”入口。
- Hermes 群聊和更清晰的运营导航可吸收，但必须先解决全局 active profile 切换造成的并发隔离问题。
- 媒体生成队列只有在同时具备后台任务、取消、历史、恢复、密钥脱敏和下载鉴权后才接入。
- Agency Agents 与 CLI-Anything 继续作为隔离扩展，不并入核心安装包。

## 本轮明确不直接移植

影视/TVBox/音乐下载的第三方版权、CORS、HLS 代理与授权风险；OpenMontage 的 AGPL-3.0 及多运行时依赖；外部 iframe 技能安全页；外部 WebSocket 聊天；以及任何只复制页面而不复制 Rust、路径、数据模型和恢复契约的功能。

## 能力评估

- 代码编程：强。Tulu 已形成助手工具调用、CLI-Anything、Browser Use、Agency Agents、工作区编辑和专家模板链，适合代码生成、修改、诊断和多步骤执行。主要风险是通用 Shell 权限仍然很高；本轮已限制到主窗口，但更细粒度的参数化工具协议仍需单独设计。
- 自动化办公：中上。已有 Browser Use、文件工作区、任务/Agent、内容工具和多渠道能力，适合网页操作、资料处理和流程编排；但跨应用桌面自动化、审批票据、任务恢复和幂等重试尚未形成统一内核。
- 可视化编程：中上。具备工作区树、助手面板、CLI-Anything、Browser Use 和多个可视化工具入口，但还不是节点式低代码 IDE；缺少统一的数据流画布、类型化节点契约、断点和运行追踪。
- 可视化自动办公：中。影视、音乐、OpenMontage、像素办公室等界面丰富，但这些是分立工作台，不等于统一的自动办公编排器。要提升到“强”，需加入可视化流程图、触发器、审批、运行历史、失败恢复和凭据引用。
- 对照结论：Tulu 的可用工具面更广，ClawPanel 的 Provider、部署、升级、Linux/Web/Docker 和便携治理更成熟。建议继续吸收治理契约，不复制品牌页面。

## 验证证据

- Node 回归测试：`246/246` 通过。
- Vite 生产构建：通过，生成 `dist/src/player.html`，包含按集解析逻辑且不含 localhost bridge。
- 依赖审计：`npm audit --audit-level=moderate` 为 0 漏洞。
- 静态门禁：Rust 格式、JS 语法、capability JSON、`git diff --check` 和私钥块扫描通过。

## 仍有阻断与残余风险

- 厂长源站真实请求仍被 SafeLine WAF 返回 `403 Forbidden`，Edge headless 也未取得 DOM。当前修复保证受限解析、切集重新解析、正确失败和不误播 HTML，不能宣称真实播放已经恢复。
- 多个旧语言包仍有乱码和英文占位。5 个电影缺失 key 已补齐，但 key 集合一致不代表 11 个 locale 的翻译质量合格，发布前仍需人工母语校对。
- 构建期必须配置 `XINGSHU_FULL_UPDATE_MANIFEST_URL` 才启用自动更新；未配置时按设计停用。完整的签名清单、公钥轮换、降级与恢复测试仍属于后续发布工程。
- `assistant_exec` 仍是主窗口内的通用 Shell 原语，以保留编程能力。任何主窗口脚本注入都具有高影响，因此 CSP、结构化工具、一次性审批票据和命令审计仍应继续建设。

## 模型报错降低方案（待审批，未实施）

1. 统一错误分类：将 Provider、模型、鉴权、额度、限流、上下文、网络、Gateway 和工具错误映射为稳定代码，UI 只显示脱敏说明和可执行修复。
2. 请求前校验：发送前校验模型可用性、Provider 配置、上下文预算、附件上限和 Gateway 握手状态，避免已知无效请求产生扣费或重复失败。
3. 有界重试：仅对可重试网络错误、`429` 和部分 `5xx` 使用指数退避与抖动；遵守 `Retry-After`；鉴权、参数和上下文错误不重试；所有请求带幂等/运行标识。
4. 熔断与降级：同一 Provider 连续失败后短时熔断；是否切换备用模型必须由用户预先授权，并在发送前展示价格、上下文和能力差异。
5. 流式状态机：以 session/run/request 三层所有权隔离事件，终止事件只接受一次；切换会话、停止和重试必须取消旧请求，禁止旧事件串入新会话。
6. 可恢复草稿：发送失败保留用户输入、附件引用和已生成可见内容；不持久化密钥、完整请求头或未脱敏堆栈。
7. 故障注入门禁：对超时、断流、乱序 SSE、重复终止、429、5xx、Provider 下线、Gateway 重连和模型不存在建立可重复测试，并验证不崩溃、不串线、不无限重试、不重复扣费。

审批边界：以上方案不会在本轮自动实施。建议优先批准第 1、2、3、5、7 项；备用模型自动切换和通用 Shell 结构化改造需另行确认产品策略。
